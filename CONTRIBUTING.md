# Contributing to aurelianOS

Thanks for your interest in aurelianOS.

## Before contributing

For major features or architectural changes, open an issue or discussion first.

## Development

Make changes in a feature branch rather than directly on `main`.

Example:

    git checkout develop
    git checkout -b feature/example

## Pull requests

Pull requests should:

- Clearly describe the change
- Include relevant testing information
- Avoid unrelated changes
- Follow the existing project structure

## Bug reports

Include:

- Hardware
- aurelianOS version or commit
- Steps to reproduce
- Expected behavior
- Actual behavior
- Relevant logs
